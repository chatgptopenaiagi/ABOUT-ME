## GENESIS-1 — Trading controller and research infrastructure

My objective was a coherent way to direct trading research and controlled engineering operations through Codex. The resulting controller brings together public market data, historical research, synthetic simulation, journaling and reporting. Its separately authorized cTrader demo workflow uses explicit validation and durable transaction records.

My contribution was the direction and acceptance requirements; Codex implemented and tested the controller using existing Python libraries and official cTrader tooling. Simulation, historical backtesting and broker-confirmed demo execution remain distinct. Successful engineering checks do not establish profitable trading.

## GENESIS-2 — Open-source trading research laboratory

I wanted to explore existing trading software while preserving each project's independence. The laboratory acquired ten upstream projects, retained their provenance and used separate development environments. Representative local checks passed, with optional features and partial capabilities recorded separately.

These projects include NautilusTrader, Freqtrade, Jesse, VeighNa, LEAN, TradingGym, TradingGoose-Studio, ta4j, OpenStock and Qbot. Their software belongs to their respective authors and contributors. My role concerned the laboratory's purpose and priorities; Codex performed the documented acquisition, integration and verification work.

## GENESIS-3 — Windows software capability awareness

I proposed that an engineering agent should first understand the tools already available to it. GENESIS-3 records software identities, executable locations, environments, versions and verification evidence. It distinguishes installation records from actual functional tests and keeps older observations as history.

This makes tool reuse a practical engineering decision, rather than an assumption that another installation is needed.

## GENESIS-3.1 — Capability relationship intelligence

The next direction was to connect individual capabilities with dependencies, compatible environments and previous outcomes. The implemented engine supports graph queries, alternative selection, scoped composition, dependency-risk reasoning, workflow reuse and causal error memory.

These are evidence-based engineering aids with explicit uncertainty. A proposed combination is not automatically a tested integration, and a recommendation does not authorize execution. The advanced work continued alongside the financial platform.

## GENESIS-4 — Simulated financial control

I defined the objective of a unified interface for accounts, payments, trading research, transactions, accounting and reports. Codex implemented the local Financial Control Hub using existing tools, a SQLite double-entry ledger, an API, a dashboard and an MCP interface.

Recorded acceptance demonstrated a synthetic EUR 100 deposit, EUR 25 purchase and EUR 75 final balance, with reconciliation and duplicate protection. Real financial connectors remain future work; the prepared SQL Server adapter covers snapshot persistence rather than replacing the operational ledger.
